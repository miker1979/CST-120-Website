August 13, 2026 · Haunted Echoes Studios / The 9th Vessel

Grounded human-looking ghost presentation is locked

The game's apparition direction now avoids the familiar glowing, transparent ghost shorthand. Spirits should initially register as physically present people whose period clothing, sound, behavior, and impossible movement gradually reveal that something is wrong.

  • Removed glow, blue tint, automatic transparency, floating, and constant spectral mist from the standard ghost language.
  • Kept ghosts fully audible through footsteps, breathing, crying, whispers, period dialogue, tools, doors, chains, and environmental disturbances.
  • Established solid human silhouettes, obscured facial detail, era-appropriate clothing, grounded movement, and subtle visual wrongness as the baseline.
  • Reserved stronger distortion and supernatural visual changes for phase shifts, attacks, and disappearances.
  • Preserved distinct identities for the eight miner spirits through their professions, work clothes, injuries, tools, dialogue, and encounter behavior.
  • Kept story-critical apparitions visually distinct without exposing their identities, roles, or deeper connections.

Design goal: players should sometimes approach or speak to an apparition before realizing they are interacting with the dead.

August 11, 2026 · Ghostline Labs / ChoiceMaker

ChoiceMaker becomes a reusable developer-facing narrative validation engine

ChoiceMaker moved beyond its original Jerome-specific proof-of-concept role and now has a generic core designed to help game developers define, test, and validate branching outcome logic.

  • Added a generic developer model for projects, state variables, ending definitions, rule conditions, operators, validation issues, and evaluation results.
  • Built a ProjectValidator that detects duplicate IDs, unknown variables, invalid operators, invalid comparison values, enum mismatches, range violations, and empty ending definitions.
  • Built an EndingEvaluator that evaluates every ending against supplied game state, reports why rejected endings failed, and resolves the highest-priority valid outcome when multiple endings match.
  • Expanded the automated suite to 46 tests with 46 passing, 0 failed, and 0 skipped.
  • Created a generic non-Jerome developer demo proving that multiple endings can match simultaneously while priority determines the resolved ending.
  • Published a dedicated ChoiceMaker developer-preview page with an interactive browser demonstration while keeping Jerome-specific logic and spoilers private.

Next: create a portable ChoiceMaker project format and save/load workflow so developers can define projects without recompiling C#.
